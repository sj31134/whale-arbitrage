# 개인 계좌 잔고 관리

개인 Mac 터미널에서 실행한다. `status`는 등록 기록과 마지막 잔고 기준시각을 보여 준다. 키나 은행 계좌번호를 입력할 필요 없이 실행할 수 있다.

```sh
python3 -m private_accounts status
```

| 기관 | CLI 이름 | 수집 범위 | 첫 등록 |
| --- | --- | --- | --- |
| 한국투자증권 | `kis` | 표준 CSV에 입력한 주식·현금 잔고 | `import-csv kis` |
| 미래에셋증권 | `mirae` | 표준 CSV에 입력한 주식·현금 잔고 | `import-csv mirae` |
| 메리츠증권 | `meritz` | 표준 CSV에 입력한 주식·현금 잔고 | `import-csv meritz` |
| 나무증권(NH투자증권) | `namuh` | 표준 CSV에 입력한 주식·현금 잔고 | `import-csv namuh` |
| 바이낸스 | `binance` | 현물 지갑의 가용·잠긴 수량 합계, USDT 기준 평가 | `connect binance` |
| 업비트 | `upbit` | 키가 속한 포켓의 자산별 가용·잠긴 수량 합계, KRW 기준 평가 | `connect upbit` |

한 기관에 계좌·포켓이 여러 개면 각 명령에 `--account isa`처럼 별칭을 붙인다. 기본값은 `main`이다. 별칭으로 실명이나 계좌번호를 쓰지 않는다.

## 엑셀과 API 설정으로 시작하기

개인 Mac에서 이 프로젝트를 사용하면 엑셀만으로 계좌를 조회할 수 있다. Python 환경에 `openpyxl`이 필요하다. 처음 설정할 때는 아래 명령을 순서대로 실행한다. 엑셀과 키 설정만 준비하는 과정에는 거래소 접속이나 Swift 빌드가 없다.

```sh
python3 -m private_accounts setup-local
python3 -m private_accounts status
python3 -m private_accounts dashboard
```

- **잔고 원본**은 `private_accounts/accounts_stocks.xlsx`다. 열 이름은 `증권사, 계좌, 종목, 평가손익, 수익률, 보유주식수, 평가금액, 매입단가, 현재가`를 사용한다. 수익률은 Excel 퍼센트 형식으로 저장한다. 평가금액 셀의 서식에는 KRW(₩), USD(US$), USDT 중 하나가 명시되어야 한다. 파일 수정시각은 화면에 별도로 표시한다. 엑셀은 메모리에서 읽으며 포트폴리오 파일을 새로 생성하지 않는다. 파일을 편집한 뒤에는 `setup-local`로 권한과 계좌 매핑을 다시 확인하고 페이지를 새로 고친다.
- **키 원본**은 첫 설정 때 루트 `.env`에서 `private_accounts/.local/credentials.env`로 옮긴다. 루트에는 안내 주석만 남긴다. 이후 키 추가·교체는 보호된 `credentials.env`에서 한다. 개인 폴더 권한은 `0700`, 키·엑셀·연결 상태 파일은 `0600`이다. 환경파일은 로컬 평문이다. macOS에서는 설정할 때 엑셀과 개인 설정 폴더를 Time Machine 백업에서 제외하고, 개인 잔고 DB를 쓸 때도 해당 폴더의 제외 여부를 확인한다. 이 개인 파일들을 포함해 폴더 전체를 수동으로 압축·업로드하면 해당 파일도 들어갈 수 있다.
- 키 설정은 한 줄에 `이름=값`으로 입력한다. 공백이 포함된 기존 거래소 필드명과 `BINANCE_API_KEY`·`BINANCE_API_SECRET`·`UPBIT_ACCESS_KEY`·`UPBIT_SECRET_KEY`를 지원한다. 프로그램은 셸을 실행하거나 프로세스 공통 환경에 키를 내보내지 않는다. 외부 시세 서비스용 키는 거래소의 계좌 인증에 사용하지 않는다.
- 계좌 매핑은 기관명과 계좌 구분을 이용한다. 약칭만 있는 기관은 복수 계좌 구분이 유일하게 일치할 때도 **확인 필요**로 표시한다. `status`에서 계좌 별칭·엑셀 등록 여부와 키 준비·등록 기록을 확인할 수 있다. 국내 증권사 키는 실제 인증에 쓰지 않는다. 기관의 자체 약칭을 확인한 경우 보호 파일에서 해당 키 쌍의 기관 접두어를 표의 CLI 이름(예: `kis`)으로 맞추고 `setup-local`을 다시 실행한다. 엑셀에 없는 계좌는 미수집으로 표시한다.
- 계좌별로 에이전트용 데이터를 확인하려면 `python3 -m private_accounts agent-view kis --account 별칭 --source workbook`을 실행한다. 별칭은 `status`에서 확인한다. 기본값 `latest`는 같은 기관·별칭의 저장된 잔고 기준시각과 엑셀 수정시각을 비교한다. `--source snapshot`으로 API·CSV 잔고만 조회할 수도 있다. 한 계좌·한 평가통화 안에서 비중을 계산하며, 두 출처의 금액을 합산하지 않는다.
- API 사용을 시작할 때는 아래의 거래소별 읽기 전용 권한을 확인한 뒤, `build`를 한 번 실행하고 `connect-env binance`, `connect-env upbit`, `sync-all` 순으로 실행한다. 각 명령 앞에 `python3 -m private_accounts`를 붙인다. `connect-env`는 선택한 거래소 키 쌍만 로컬 파이프로 서명 수집기에 전달한다. 실인증에 성공해야 키체인에 등록한다. 엑셀에서 해당 거래소의 계좌가 하나면 그 별칭을 쓰며, 여러 개면 직접 `--account 별칭`으로 선택한다. 바이낸스는 현물 지갑만 조회한다.

## 거래소 키 등록과 갱신

1. Mac에 Python 3.9 이상과 Xcode Command Line Tools가 필요하다. 처음 체크아웃했거나 Swift 수집기 소스가 바뀌었으면 저장소 루트에서 `python3 -m private_accounts build`를 실행한다.
2. **바이낸스**에서 이 수집기 전용 HMAC 키를 만든다. 읽기와 접속 IP 제한을 켜고 사용할 공인 IP만 등록한다. 거래·마진·선물·옵션·이체·출금 권한을 모두 끈다. 수집기가 매번 거래소의 권한 응답을 확인한다. 위험 권한이 켜져 있거나 필수 항목이 없거나 해석할 수 없는 권한 필드가 있으면 잔고 조회 전에 중단한다. [바이낸스 키 권한 명세](https://developers.binance.com/docs/wallet/account/api-key-permission)
3. **업비트**에서 사용할 포켓을 선택하고, 개인 Mac의 허용 공인 IP와 **자산조회 한 가지**만 지정한 키를 만든다. 수집기는 이 권한 설정을 자동 판별할 수 없으므로 발급 화면에서 본인이 확인한 뒤 터미널에 `READONLY`를 입력한다. 이후 권한을 바꾸거나 키를 교체할 때도 발급 화면을 확인한다. [업비트 키 발급](https://docs.upbit.com/kr/docs/api-key) · [계좌 조회](https://docs.upbit.com/kr/reference/get-balance)
4. 아래 명령을 실행하고 각 키를 **본인 Mac 터미널의 숨김 입력란**에 입력한다. 키는 인증·조회 성공 후 macOS 로컬 키체인에 저장한다. `connect`는 키 등록까지 수행하며, `sync-all`이 첫 잔고를 저장한다.

```sh
python3 -m private_accounts connect binance
python3 -m private_accounts connect upbit
python3 -m private_accounts sync-all
python3 -m private_accounts status
```

다음 갱신에도 `sync-all`을 실행한다. 특정 계좌만 갱신하려면 `sync upbit --account main`을 쓴다. 각 명령 앞에는 `python3 -m private_accounts`를 붙인다. 한 거래소가 실패해도 등록된 다른 거래소는 계속 갱신하고, 마지막에 실패한 별칭을 표시한다. 바이낸스 선물·마진·Earn 및 체결내역은 수집 범위 밖이다.

공개 시세를 한 번에 받아 잔고 수량에 곱한다. 업비트 원화와 바이낸스 USDT 현금은 해당 평가통화로 1이다. 직접 거래쌍이 없거나 시세 조회가 실패하면 수량은 보존하고 해당 자산의 평가액은 비운다. [업비트 원화 시세](https://docs.upbit.com/kr/reference/list-quote-tickers) · [바이낸스 현물 계좌·시세 명세](https://github.com/binance/binance-spot-api-docs/blob/master/rest-api.md)

## 국내 증권사 잔고 가져오기

현재 확인한 공식 자료에서는 개인이 발급받는 인증키에 대해 증권사 서버에서 주문을 차단하는 설정 절차를 확인하지 못했다. 메리츠 MCP의 조회 전용 설정은 해당 프로그램에 적용된다. 국내 네 곳은 개인 키를 받지 않고 아래 형식의 CSV로 관리한다. [한국투자증권](https://apiportal.koreainvestment.com/apiservice) · [미래에셋증권](https://securities.miraeasset.com/hki/hki3032/n05.do) · [메리츠증권](https://openapi.imeritz.com/mcp) · [나무증권](https://www.nhplug.com/apiservice)

증권사에서 잔고를 내려받은 다음, 아래 네 열만 있는 CSV를 **저장소 밖**에 준비한다. 아래 금액과 시각은 사용 예시다. 한 파일에 **한 계좌의 기준시각 현재 전체 잔고**를 담는다. 앱별 원본 파일 서식은 자동 변환하지 않는다.

```csv
symbol,quantity,currency,market_value
005930,10,KRW,700000
KRW,300000,KRW,300000
AAPL,2,USD,400
```

- `symbol`은 종목코드다. 스프레드시트에서는 텍스트 형식을 사용해 앞자리 0을 보존한다. 현금은 통화코드를 쓴다.
- `quantity`는 보유 수량, `currency`는 평가통화, `market_value`는 **그 수량 전체의 평가액**이다. 평가액을 모르면 빈 칸으로 둔다. 숫자에 천 단위 쉼표를 넣지 않는다.
- 예수금을 비중에 포함하려면 별도 현금 행을 넣는다. 전량 처분한 계좌는 수량·평가액이 0인 행을 한 줄 넣는다. 현금·롱 잔고를 지원한다.
- `--as-of`에는 원본 잔고의 실제 기준시각과 시간대를 적는다. 같은 계좌·시각·내용은 한 번만 반영한다. 같은 시각의 다른 내용은 거부하고, 과거 자료는 이력으로만 추가한다.

```sh
python3 -m private_accounts import-csv kis ~/Downloads/kis.csv --account isa --as-of 2026-11-20T16:00:00+09:00
```

## 투자 관리 화면

Finder에서 `private_accounts/open_dashboard.command`를 열거나 저장소 루트에서 `python3 -m private_accounts dashboard --open`을 실행한다. 최신 계좌 자료, 통화별 평가액, 분야별 보유 목록, 10개 애널리스트의 관측과 현금 일정을 본다. 종목을 누르면 분야 공통 자료와 종목에 직접 연결된 근거를 따로 볼 수 있다. 상세에서 담당·연결어를 수정하고 근거와 현금 필요일을 기록한다. ‘계좌 원장’은 엑셀·스냅샷 원본별 상세다.

Finder 실행 파일은 같은 프로젝트의 이전 서버를 식별해 교체하고 고정 북마크를 유지한다. 대시보드가 열려 있는 동안 공개 시세와 변수를 자동 수집한다. 수량은 엑셀·CSV 또는 마지막 인증 잔고의 기준시각을 따른다. 거래소 수량을 새로 확인할 때는 기존 `sync` 명령을 사용한다. [정보 범주와 실행 방법](../data/analysts/README.md)

## 개인 화면과 에이전트용 데이터

```sh
python3 -m private_accounts dashboard
python3 -m private_accounts agent-view kis --account isa
```

Finder의 실행 파일을 열면 기본 브라우저에서 같은 Mac의 투자 매니저가 열린다. 매니저·계좌 화면은 표시 중 5초마다 로컬 평가를 읽고 포트폴리오는 15초마다 비중과 스트레스를 갱신한다. 보고서, 수량 원장과 입출금 조정 기간 성과에는 각 기록의 기준시각이 남는다.

업비트 원화마켓과 바이낸스 USDT 현물은 공개 웹소켓을 구독한다. Python의 `websockets.sync`를 사용할 수 없으면 REST로 갱신한다. 주식은 코스피·코스닥·나스닥·NYSE·AMEX의 시가총액 앞 페이지와 순환 페이지를 확인한다. 국내 ETF는 대표 표본 4개와 공개 전체 목록의 다음 묶음을 확인한다. 한 회차가 끝나면 30초 뒤 다시 조회하므로 개별 종목의 갱신 간격은 다르다. 화면에 표시하는 시세 시각은 원천 관측 기준이다. 바이낸스 미니티커 시각은 이벤트 또는 집계창 종료 시각이다. 실패 시 마지막 성공값을 사용하며 식별이 모호하거나 환율이 없으면 원장 평가액을 표시한다.

금리·원달러·신용 스프레드·VIX는 발표일이 있는 FRED 자료를 기본 30분 간격으로 조회한다. BTC·ETH의 업비트 상위 5호가, 바이낸스 USDT 무기한 펀딩 및 미결제약정은 5분 간격의 공개 표본이다. `research-import`는 FRED 8개 계열에 관측일·수치 배열(`day`, `value`)을 받고, `upbit_sample`과 `FX_USDKRW`로 공개 원문 확인분을 기록한다. 원천 실패, 마지막 성공과 원문 확인분을 구분한다.

`daily-review --refresh`는 다섯 담당의 공통 원천을 갱신한다. 일일 투자 검토의 **보유 주식 하락 경보**는 연결 가능한 상장 주식마다 마지막 독립 검증 거래일과 60일선·낙폭 조건을 표시한다. 휴장, 일봉 지연, 기업행동이나 종가 검증 보류 시 표시된 거래일과 상태를 먼저 확인한다. [현금 대안 검증](../agents/equities/memos/2026-11-24-cash-review.md)

`agent-view`는 선택한 계좌의 기준시각·종목·평가통화·비중(%)만 JSON으로 출력한다. 비중은 **한 계좌 안에서 같은 평가통화끼리** 계산한다. 같은 통화의 자산 중 평가액이 하나라도 빠져 있거나 합계가 0이면 해당 통화의 비중은 모두 `null`이다. 외부 전송과 에이전트로의 자동 전달은 없다.

## 분야별 포트폴리오 검토

`python3 -m private_accounts portfolio-review equities`로 해당 분야의 검토 대상을 본다. 분야 값은 `whale`, `crypto`, `real_estate`, `equities`, `us_small_cap_high_beta`다. 실행 시 키나 외부 API를 사용하지 않는다. 응답의 종목·계좌 별칭·비중은 개인용이다. 분석 기준과 신규 후보의 근거는 [투자 운영 기준](../agents/INVESTMENT_MANDATE.md)에서 확인한다.

- 계좌마다 엑셀 수정시각과 스냅샷 기준시각 중 더 최근 자료를 선택한다. 시각이 같으면 스냅샷을 사용한다. 빈 보유 배열은 해당 자료에서 선택된 분야에 배정된 행이 없다는 뜻이다. 자료 자체가 없는 기관은 `providers_without_data`에 표시한다. 엑셀 수정시각과 실제 평가시점은 다를 수 있다.
- 거래소의 법정현금 외 자산은 코인이 주 담당이고 고래가 신호를 검토한다. 증권사 미분류 상품은 주식 담당에게 유형 확인을 요청한다. 미국 소형·고베타 담당 배정은 시총·베타를 검증하라는 뜻이다. 그 자체로 분류가 확정되지는 않는다. 실물은 계좌 원천에 행이 있어야 표시되며 미등록 부동산은 추정하지 않는다.
- 개별 배정이 필요하면 개인 Mac의 `private_accounts/.local/agent_roles.json`에 JSON 행 목록을 둔다. 각 행의 `provider`, `account`, `symbol`은 로컬 조회의 기관 코드·계좌 별칭·종목과 정확히 일치해야 한다. `role`은 `crypto`, `equities`, `real_estate`, `us_small_cap_high_beta`, `cash`, `other` 중 하나다. `cash`와 `other`는 분야별 보유 분석에서 제외하고 계좌별 비중 분모에는 유지한다. 파일 권한은 소유자 읽기·쓰기(0600)로 설정한다. 이 파일은 Git 및 배포에서 제외된다.

## 저장·해제

- API 키는 수집기 실행 파일이 macOS 키체인 API로 읽고 쓴다. 키체인 항목은 iCloud 동기화 대상에서 제외한다. 재빌드 뒤에는 macOS가 다시 접근 승인을 요청할 수 있다. 접근을 승인하기 전에 표시된 프로그램을 확인한다.
- 라벨, 잔고, 평가액, 기준시각은 `~/Library/Application Support/whale_tracking/accounts/balances.sqlite3`에 보관한다. 비어 있는 상태에서 `status`나 대시보드를 실행해도 DB를 만들지 않는다. DB 파일은 소유자만 읽고 쓸 수 있는 일반 SQLite이며 별도 DB 암호화는 없다. 같은 macOS 사용자 권한으로 파일을 읽는 다른 프로그램에는 이 권한이 경계가 되지 않는다.
- 특정 거래소의 로컬 키를 지우려면 `python3 -m private_accounts disconnect binance --account main`을 쓴다. 저장한 잔고 이력은 보존한다. 유출 우려가 있거나 연결을 완전히 종료할 때는 거래소 관리 화면에서 발급 키도 폐기한다.

## 일일 투자 검토

자동 수집이 실패했을 때는 공개 원천의 공식 목록을 확인한 사람이 조회 시각과 관측값을 함께 반영할 수 있다. `python3 -m private_accounts research-import <원천> --checked-at <시간대가_있는_ISO_확인시각>`은 표준 입력으로 JSON 배열을 받는다. 개인 계좌는 이 입력에 사용하지 않는다.

| 원천 | 공식 화면에서 가져올 필드 | 표시 범위 |
| --- | --- | --- |
| `upbit` | `market`, `trade_timestamp`(밀리초), `trade_price`, `signed_change_rate`(비율) | 업비트 원화마켓별 마지막 체결 |
| `edgar` | `title`(CIK 포함), `url`(SEC 원문 색인), `time`(시간대 포함) | 최근 10-Q 및 10-Q/A 접수 |
| `dart_recent` | `company`, `title`, `url`(DART 접수번호 원문), `day`(YYYY.MM.DD), `time`(HH:MM) | 조회한 최근공시 목록의 해당 페이지 |

대시보드에서 API의 마지막 성공·실패와 공식 화면에서 보완한 시각을 각각 확인할 수 있다. 수집 결과를 합칠 때 같은 원화마켓은 더 최근 체결을, 같은 공시는 접수 원문 한 건을 표시한다. DART 최근공시 화면과 OpenDART 정기공시 API는 조회 대상이 다르다. 검증을 통과한 목록은 Mac의 `private_accounts/.local/`에 저장한다. 반영 뒤 `python3 -m private_accounts daily-review`를 실행하면 계좌와 새 공개 근거를 로컬에서 다시 대조한다.

`python3 -m private_accounts daily-review --refresh`는 공개 원천을 갱신한 뒤 로컬 대시보드의 ‘일일 투자 검토’에 결과를 저장한다. KST 날짜별로 보관하며 같은 날짜의 재실행은 최신 보고서를 반영한다. 명령은 성공 여부만 출력한다. 현재 포지션의 엑셀 평가손익과 평가액 통화가 명시적으로 일치할 때만 집계한다. 스냅샷이 더 최근이면 원가 없는 스냅샷에 예전 엑셀 손익을 붙이지 않는다.

통화별 순평가손익은 확인된 보유분의 손익 합계다. 손실 기여도는 해당 보유 행의 손실 절댓값을 같은 통화의 확인된 손실 절댓값 합계로 나눈 값이다. 현재 자료의 모든 해당 통화 보유분에 손익과 평가액이 있고 평가액 합계가 양수일 때, 원가 회복 필요 수익률을 ‘순평가손실 ÷ 현재 평가액’으로 계산한다. 실현손익·세금·수수료·입출금·미수집 계좌를 포함한 누적 투자성과는 별도 원장이 필요하다. 일일 검토는 최신 직접 근거도 보관한다. 첫날에는 연결된 최신 근거를 보여 주고, 이후에는 직전 검토일과 대조해 추가되거나 내용이 바뀐 근거를 표시한다. 자료의 날짜와 계좌의 기준일은 각각 확인할 수 있다.

공개 수급을 함께 반영하려면 같은 명령에 `--public-flows`를 붙이고 표준입력에 JSON 배열을 전달한다. 행의 문자열 필드는 `market, period, as_of, metric, unit, theme, net, source`다. 기준일은 YYYY-MM-DD, net은 부호 있는 십진수, source는 공개 HTTPS 원문이다. 같은 시장·기간·기준일·측정치·단위·원천의 자료만 서로 비교한다. 단일 ETF 순설정액을 산업 전체 유입액으로 해석하지 않는다. 원문에 없는 금액은 입력하지 않는다. 개인 계좌 식별자나 보유내역은 공개 자료 입력에 넣지 않는다.

일일 검토 순서는 예정된 현금 지출과 유동성, 손실 기여 상위 보유분의 가설·새 공시, 국내 기관·외국인 순매수와 해외 ETF 순설정의 지속성, 후보별 상승 촉매·약세 시나리오·무효화 조건이다. 사모펀드는 공시된 범위와 보고 지연을 기록한다. 고빈도·AI·알고리즘 신호는 스프레드·거래대금 등 근거를 붙인 연구 또는 비용을 반영한 모의검증에서 다룬다. 직접 거래는 보류 중이다.

### 미국 반도체 마감과 한국 시초가 경보

일일 검토는 직전 미국 정규장에서 반도체 표본 두 개가 함께 급락했는지 확인해 화면의 **미국 반도체 장 마감 · 한국 시초가 위험**에 판정, 미국 거래일, 표본별 등락률·원문·확인시각을 표시한다. 표본은 섹터 ETF `SOXX`와 종목 `NVDA`의 공개 종가 등락률이다. 보유 목록과 계좌 자료는 이 판정에 쓰지 않는다.

- **대상 거래일**은 검토 시각의 KST 날짜 하루 전이며, 그날이 주말이면 직전 금요일이다. 마감은 미국 동부 16시, 코드에 등록한 조기 마감일(2026-11-27, 2026-12-24, 2027-11-26, 2028-11-24)은 13시로 본다. 미국 휴장일은 자체 판별하지 않는다. 휴장 다음 날에는 해당 날짜의 종가가 없어 판단 보류로 남으므로 거래소 달력을 확인한다.
- **인정하는 관측**은 대상 거래일의 미국 종가 등락률 가운데 확인시각이 그 마감 이후, 검토 시각 이전인 값이다. 시장 스캔, `market-cases` 독립 입력, 야간 보충 수집 중 표본별로 가장 늦게 확인된 값을 쓴다. 다른 거래일의 값이나 마감 전에 받은 값은 쓰지 않는다.
- **판정**은 세 가지다. 두 표본의 등락률이 모두 −5% 이하이면 `경보 · 한국 반도체 시초가 갭 하락 위험`, 두 값이 있으나 조건에 못 미치면 `동반 급락 조건 미충족`, 한쪽이라도 없으면 `판단 보류 · 같은 미국 거래일의 종가 두 건 확인 필요`다.

`daily-review --refresh`는 가장 먼저 이 표본을 점검한다. 마감이 지났는데 빠진 표본이 있으면 그 표본만 공개 차트에서 다시 받아 `private_accounts/.local/overnight_screen.json`에 저장한다. 두 값이 이미 있으면 재수집하지 않고, 실패한 시도는 마지막 성공값을 지우지 않는다. `--refresh` 없이 실행하면 이미 저장된 관측만으로 판정한다.

자동 수집이 실패하면 직접 확인한 종가를 `research-import market-cases`로 넣는다. 필드는 [일간 이상 움직임과 시장구조](#일간-이상-움직임과-시장구조)의 `market-cases`와 같고 `market`은 `US`, `day`는 대상 거래일, `change_pct`는 종가 등락률(%)이다. 이 두 표본의 미국 종가 행은 `kind`와 `source`가 아래와 정확히 일치할 때 고정 도메인 목록 밖의 Stock Analysis 과거가격 페이지를 원문으로 받는다.

| symbol | kind | source |
| --- | --- | --- |
| `SOXX` | 섹터 ETF 표본 | `https://stockanalysis.com/etf/soxx/history/` |
| `NVDA` | 종목 | `https://stockanalysis.com/stocks/nvda/history/` |

경보는 현금 유지 대안과 시초가 체결비용을 다시 검토하라는 신호다. 한국 시초가의 실제 갭이나 개별 보유 종목의 손익을 예측한 값이 아니다. 두 표본은 노출이 겹치므로 독립된 두 근거로 세지 않는다. 보유 판단에는 국내 반도체의 시장 대비 강도, 외국인 순매수 회복 여부 같은 별도 근거가 필요하다. 기준 −5%는 코드에 고정한 선별 값이며, 이 기준의 과거 적중률을 검증한 메모는 아직 없다.

## 투자 매니저와 분야별 분석실

`python3 -m private_accounts dashboard --open` 또는 `open_dashboard.command`로 투자 매니저를 연다. 상단 메뉴에서 고래, 코인, 부동산·경매, 주식·ETF, 미국 소형·고베타 주식, 포트폴리오 현황, **신규 대장주 발굴(`/discover`)**, 퀀트 연구, 전략 관리, 가설 연구장으로 이동할 수 있다.

### 포트폴리오 외 신규 대장주 발굴

상단 **신규 대장주 발굴(`/discover`)** 메뉴 또는 `python3 -m private_accounts discover --refresh` 명령은 공개 수집기에 개인 보유 목록을 전달하지 않고 한국(`KRX`)·미국(`NASDAQ`·`NYSE`) 주요 병목 산업 및 당일 수급 급부상 후보를 **6대 변수(수급 25점 · 차트/시장대비 상대강도 25점 · 이슈/내재가치 20점 · X/SNS 관심·심리 10점 · 글로벌 흐름 10점 · 지정학/공급망 10점)**로 채점해 일자별 연속 포착 일수(`streak`), 당일 등락률(`change_pct`), 1차·2차 분할 진입가와 방어 점검선(`-8%`), 신규 진입(`NEW`) 여부를 기록한다. 화면에서는 **종합 총점·수급·차트 상대강도·목표가 상승여력·지정학·SNS 화제성 6종 정렬**과 전체 후보 보기를 지원하며, 카드 하단의 **이 종목으로 가설 자동 채우기**를 누르면 가설 연구장(`/research`)에 기준가·비교지수(`KODEX 200` / `SPY`)·수수료(`bp`)·시나리오 3관문 사전 시뮬레이션이 자동으로 채워진다. 내 계좌 보유 종목 대조는 Mac 로컬 화면 렌더링 시점에만 수행해 외부 대장주를 독립 추적하며, X 공식 API 토큰 미연결 시에도 글로벌 커뮤니티 언급량(`ApeWisdom`) 및 **X·SNS 게시물 검증 등록기**로 조용한 기관 매집과 루머·단기 과열 여부를 구분한다.

Finder에서 `open_dashboard.command`를 더블클릭하면 기본 브라우저에서 매니저가 열린다. 기본 실행은 Mac 내부 고정 포트 18765와 개인 폴더에 저장된 접속 정보를 사용한다. 확인된 구버전 서버의 종료 권한이 없을 때는 대체 고정 포트 18766을 선택해 같은 Finder 바로가기에 저장한다. 새 버전은 다음 업데이트 때 자체 종료 요청을 처리한다. Finder에서 공개 환율 원문에 연결할 수 있고 기존 서버의 주요 시세 원천이 모두 DNS 실패 상태라면 실행기가 같은 고정 포트에 서버를 다시 시작한다. 이미 실행 중인 서버를 확인하고 재사용하며, 꺼져 있으면 백그라운드에서 시작한다. 실행 창을 닫아도 계속 동작한다. 처음 열린 새 매니저 페이지를 즐겨찾기에 추가하면 다음 실행에도 같은 주소를 쓴다. Mac 재시동이나 로그아웃 후에는 실행 파일을 한 번 연다. 별도 로그인 시작 항목은 설치하지 않는다.

Mac의 고정 서버가 실행 중이면 해당 포트의 `/start`를 즐겨찾기하고 **투자 대시보드 열기**를 누른다. 시작 페이지는 Mac 기본 브라우저로 매니저 화면을 연다. 자동 열기가 제한된 환경에서는 같은 페이지의 파일 선택으로 로컬 `투자 대시보드.webloc`을 읽어 현재 탭에서 연다.

이전 버전의 임시 주소는 새 즐겨찾기로 바꾼다. Safari 등 기본 브라우저의 자동 열기를 사용할 수 없는 경우 서버가 실행된 상태에서 Finder로 `private_accounts/.local/투자 대시보드.webloc`을 열 수 있다. 이 바로가기와 접속 정보는 로컬 전용이다. 고정 포트를 다른 서비스가 차지하면 실행기가 상태를 알려 준다. 개발용 독립 임시 세션은 `dashboard --port 0 --open`을 쓴다. 일반 실행의 자료 갱신 주기는 서버가 시작될 때 결정된다.

작업 지시는 Codex·Claude·Cowork·Antigravity의 [공통 작업 접수](../agents/manager/WORK.md)로 받는다. 예를 들어 “주식과 코인 담당의 수급 자료를 점검하고 비교 결과를 게시해”라고 요청하면, 해당 분야의 지침에 따라 검토한 뒤 이 화면에 결과를 게시한다. 브라우저는 저장한 내용을 표시하며 Mac에서 추론 프로세스를 띄우지 않는다. 게시 후 페이지를 새로고침한다.

- **투자 매니저** 첫 화면에서 전체 보유 종목과 통화별 평가를 보고, 종목을 선택해 담당·근거로 이동한다. 다섯 담당의 배정·최신 결과, 열 개 데이터 범주와 원천 상태, 주식 시장 브리핑, 종합 보고서가 이어진다. 종합 보고서에는 실제로 인용한 담당 보고서가 연결된다. 일일 검토는 다섯 담당의 공통 원천을 갱신하고 주식 시세·일봉을 우선 계산한다. 토큰화 주식은 시장 스캔에서 별도 확인한다. 전체 및 개별 범주의 수동 수집은 기존 명령과 화면에서 이용한다.
- **담당 화면**에서는 판단, 근거의 출처·기준시각, 하방 위험, 재검토 조건과 이전 결과를 확인한다. 우측에서 등록 변수, 누락 자료, 마지막 수집 상태를 확인하거나 변수를 보충한다. 기존 로컬 모델의 결론은 별도 기록에서 열람할 수 있다.
- **포트폴리오 현황**에서는 계좌·종목 연결, 정보 범주별 수집과 일일 검토를 관리한다. 공개 원천 수집은 기존 CLI와 이 화면의 갱신 기능을 사용한다. 새로 수집할 때 저장된 보고서의 기준시각·근거는 그대로 보존된다.

### 분석 결과 게시

선점한 세션이 저장소 루트에서 `python3 -m private_accounts publish-report <담당>`을 실행해 UTF-8 JSON 한 건을 표준 입력으로 전달한다. 담당은 `whale`, `crypto`, `real_estate`, `equities`, `us_small_cap_high_beta`, `manager` 중 하나다. 성공하면 보고서 ID만 출력된다. 같은 내용으로 재시도하면 같은 ID를 돌려준다.

| 필드 | 기록할 내용 |
| --- | --- |
| `title`, `conclusion` | 검토 대상과 관측에 근거한 결론 |
| `as_of`, `status` | 시간대가 있는 ISO 8601 기준시각과 판정. 판정값은 `검토 완료`, `관찰`, `판단 보류` |
| `downside`, `revisit` | 하방 위험·자료 한계와 판단을 다시 검토할 조건 |
| `sources` | 근거별 `label`, `as_of`, 선택적 공개 HTTPS `url`. 로컬 기록에는 원천 이름과 관측시각을 기입한다. 근거가 없으면 빈 배열과 판단 보류를 사용한다. |
| `inputs` | 매니저 종합에 참여한 분야별 보고서 ID 한 건씩. 분야 보고서는 생략한다. |

예를 들어 다음은 입력 형식을 보여 주는 가상 자료다.

```json
{
  "title": "수급 원천 점검",
  "as_of": "2026-01-01T09:00:00+09:00",
  "status": "판단 보류",
  "conclusion": "같은 시각의 호가 자료를 확보해야 한다.",
  "downside": "시차가 있는 자료를 비교하면 수급 방향을 잘못 읽을 수 있다.",
  "revisit": "두 원천의 관측시각과 거래 단위가 일치하면 다시 검토한다.",
  "sources": []
}
```

결과는 `private_accounts/.local/desk_reports.json`에 로컬 전용 권한으로 저장한다. 계좌번호·잔고 원본·키·토큰 주소는 결과 본문, 표준 출력, 공개 원문 주소에 포함하지 않는다.

### 가설 연구장과 하방 스트레스

Mac에서 기존 대시보드를 열고 **가설 연구장**으로 이동한다. 매니저 홈에는 평가일이 도래한 가설 수, 원천별 마지막 자동 성공·최근 시도·최근 관측일·수동 보완 범위가 표시된다. 수동 공시 표본이 추가돼도 자동 수집 실패 상태는 남는다.

1. **최초 판단을 저장한다.** 근거가 있는 게시 보고서, 대상과 비교지수, 통화, 두 가격의 공통 기준시각과 각각의 원문, 촉매·철회 조건·평가 예정일을 입력한다. 약세 20%, 기준 50%, 강세 30%는 연구 가정이다. 모든 가격은 하나의 평가통화로 일관되게 환산하고 두 시점의 주식분할 조정 기준을 맞춘다.
2. **비용을 반영해 비교한다.** 왕복 수수료·세금과 예상 스프레드·슬리피지를 각각 최초 투입금 대비 bp로 입력한다. 100bp가 1%다. 각 시나리오 가격수익률에서 두 비용을 차감하고 기대수익률을 확률가중한다. 손익비는 (강세 수익률 × 0.3 + 기준 수익률 × 0.5) ÷ (약세 손실률의 절댓값 × 0.2)다. 약세 손실·비음수 기준 수익 조건이 성립할 때 계산한다. 안전마진은 (기준 내재가치 − 기준가격) ÷ 기준 내재가치다. 12%는 설정 기간의 기대수익률이며 연환산하지 않는다. 이 화면의 12%·3배·20%는 연구 선별 기준이다. 각 가설 카드에는 3대 관문 통과 배지와 약세·기준가·내재가치·강세 구간을 보여 주는 시각적 가격 게이지가 함께 표시되며, 같은 통화·비교지수·비교 시작값·관측시각·평가 예정일을 가진 후보끼리 기대수익률 막대와 하방을 비교한다.
3. **사전등록 후 모의 추적을 시작한다.** 등록 이후에 관측한 대상 가격과 비교지수 값을 같은 시각·각각의 원문으로 입력한다. 평가 종료에는 추적 시작을 저장한 이후의 새 관측 두 개와 가설 판정·이유가 필요하다. 같은 제출은 한 번만 반영한다. 최초 가정과 확정한 관측을 덮어쓸 수 없다. 하방 시나리오는 기계적 자동 손절 한도가 아니라 현금 버퍼 및 기업 가설 훼손 공시 재점검 기준선이다. 모의 결과는 입력한 가격과 비용에 기반한 가격수익률이며 실제 체결·배당·임대수익·계좌 성과와 구별한다. 초과수익은 비용 후 대상 수익률에서 비용 차감 전 비교지수 가격수익률을 뺀 값이다.
4. **보유분을 점검한다.** 포트폴리오 현황 상단의 **소수 집중 · 현금 버퍼 실전 점검**에서 계좌·통화별 상위 2종목 집중도와 1단계 권장 현금 버퍼(35% 이상) 확보 여부를 확인하고, **하방 스트레스**에서 조정·급락 가정을 바꾼다. 계좌·평가통화별 반영 비중과 시나리오 손익 기여도를 표시한다. 현금과 스테이블코인, 알려진 자산과 유형 확인이 필요한 상품을 구분한다. 동일 행을 여러 분야가 분석해도 한 번만 반영한다. 미분류·미평가 행과 화폐 간 환산·부채·세금·유동성의 별도 영향은 전체 손실에 반영되지 않는다.

연구 DB는 개인 폴더의 별도 SQLite 파일이다. 조회만 하면 새 DB를 만들지 않으며 `python3 -m private_accounts research-init`으로 준비할 수 있다. 실거래·계좌 인증을 호출하지 않는다.

**백업과 복구.** 가설 연구장 하단의 연구 스냅샷은 연구 DB와 게시 보고서만 묶는다. 파일별 SHA-256, SQLite 무결성·참조, 매니저 입력과 가설의 보고서 연결을 확인한다. 복구는 같은 Mac의 별도 폴더에 새 사본을 만들며 운영 파일을 갱신하지 않는다. 동일 디스크 장애에 대비한 외부 백업, 계좌 엑셀·실잔고·키의 복구는 이 기능의 범위 밖이다. CLI에서도 사용할 수 있다.

```sh
python3 -m private_accounts research-snapshot
python3 -m private_accounts research-recover <스냅샷ID>
python3 -m private_accounts market-note YYYY-MM-DD
```

공개 수급 노트에는 해당 KST 일일 검토에 명시적으로 입력한 공개 수급 필드만 포함된다. Obsidian에서 `private_accounts/.local/market-notes`만 별도의 로컬 보관함으로 열 수 있다. 프로젝트 루트나 상위 개인 폴더를 보관함으로 지정할 필요가 없다. 외부 서비스 전송은 없다.

**실계좌 기간 성과.** 일일 검토는 계좌·평가통화별 평가액과 원천 기준시각을 Mac에 보관한다. 이전 버전에 없던 과거 평가액은 소급 생성하지 않는다. 포트폴리오 현황의 **입출금 조정 계좌 성과**에서 같은 계좌·통화·원천의 서로 다른 두 시점을 선택한다. 엑셀 수정시각은 평가시각의 상한이므로 실제 기초·기말 평가시각은 별도로 확인한다. 예수금·현물이체·환전이 포함된 평가 범위를 대조하고 외부 이동을 한 줄씩 입력한다. 확인한 무입출금은 ‘없음’으로 기록한다. 순손익은 기말 평가액 − 기초 평가액 − 순입금이다. 수정 디츠 수익률은 순손익을 기초 평가액과 잔여기간 가중 순입금의 합으로 나눈 근사치다. 대규모 현금흐름과 급격한 가격 변동이 겹치면 오차가 커질 수 있다. 가중 분모가 0 이하면 수익률 산정을 보류한다. 대조 내역을 정정하면 이전 판정도 보존된다. 실계좌 대조 기록은 공개 노트와 연구 스냅샷에서 제외된다. [산식 근거 · GIPS Handbook, Input Data and Calculation Methodology](https://www.gipsstandards.org/wp-content/uploads/2021/04/gips-standards-handbook-firms.pdf)

Codex에서도 공개 가정을 표준입력 JSON으로 게시할 수 있다. `research-register`는 문자열 필드 `report, asset, currency, benchmark, observed, entry, benchmark_entry, bear, base, bull, fees, slip, price_source, benchmark_source, catalyst, invalidate, due`를 받고 가설 ID만 반환한다. 같은 입력으로 재시도하면 같은 ID를 반환한다. `report`는 근거가 있는 실제 게시 ID, `observed`는 시간대가 있는 ISO 시각, `due`는 KST 날짜다. `research-observe start <가설ID>`는 `exit, benchmark_exit, observed, source, benchmark_source`에 추적 시작 관측값을 받는다. `research-observe finish <가설ID>`는 같은 필드에 종료 관측값을 받고 `verdict, reason`을 추가한다. 판정은 ‘가설 지지’, ‘가설 기각’, ‘판단 보류’ 중 하나다. 미관측 가격과 미검증 가정을 대신 채우지 않는다.

### 일간 이상 움직임과 시장구조

거래소 달력에서 한국·미국의 마지막 **완료 거래일**을 각각 확인한 뒤 실행한다. 날짜 인자는 해당 거래소 현지 날짜다. 오전 8시 브리핑은 두 시장에 필요한 날짜가 다를 수 있다. 장중 지수·시장 조치는 발표 시각을 붙여 종가 분석과 나눠 기록한다.

```sh
python3 -m private_accounts market-scan --kr-day YYYY-MM-DD --us-day YYYY-MM-DD
python3 -m private_accounts research-import market-cases --checked-at '시간대가 포함된 확인 시각'
python3 -m private_accounts research-import market-structure --checked-at '시간대가 포함된 확인 시각'
python3 -m private_accounts market-crosscheck
```

첫 명령은 공개 결과만 출력한다. 차트 원천은 배당·분할 조정 종가 기준이며, 지수·공개 마감자료와 비교 표본을 구분한다. 미국 3개 거래소와 국내 2개 시장의 시총 첫 페이지(각 최대 60종목), 고정 종목과 섹터 ETF를 사용한다. 절대 일간 등락률 3%, 직전 20거래일 대비 표준화 편차 절댓값 2, 장중 고저 폭/종가 5% 중 하나를 넘거나 경계에 해당하면 표시한다. 같은 표본의 통과 후보는 절대 등락률 순으로 최대 5개다. 해외 현물은 미국부터 운영한다. 원천·시각이 일치하는 호가 스프레드는 (매도－매수)/중간가 × 10,000 bp이며, Kraken USD 표본은 응답 수신 시각이다. 현물 호가는 거래장소·시각을 확보한 공개 원문의 독립 입력도 받는다. 차익·비차익 프로그램 순매수는 원천 표의 단위를 확인한다. 최근 5개 관측일과 관측일 목록을 함께 보관한다.

독립 입력은 공개 연구자가 시장에서 선정한 사례만 받는다. JSON 배열 각 행에 아래 필드를 넣는다. 전달하는 원문 도메인은 코드의 고정 목록으로 제한한다.

| 입력 종류 | 필드와 기준 |
| --- | --- |

## 주식 계좌 시세와 거래일 이력

Mac에서 `open_dashboard.command`를 열면 고정된 로컬 투자 매니저로 연결된다. 매니저의 종목명은 담당·근거로, 옆의 **차트**는 그 보유 종목의 가격 이력으로 연결된다. 국내·미국 거래소의 공개 상장목록을 수집한 다음 Mac에서 엑셀의 종목과 연결한다. 공개 수집기는 계좌별 목록이나 별칭을 전달받지 않는다. 수량의 기준은 엑셀 수정시각 또는 더 최근의 계좌 스냅샷이며 매수·매도에 따른 수량 변경은 원장에 반영해야 한다.

- 공개 목록은 약 30초 간격으로 선두 페이지와 다음 페이지를 순환한다. 종목별 최신성은 거래소의 시세 시각·지연·마감 상태로 확인한다. 평가액은 수량과 단가로, 평가손익은 같은 통화의 확인된 원가로, 비중은 같은 계좌·평가통화 내에서 다시 계산한다. 외화는 확인된 환율이 필요하며, 바이낸스 현물 자산을 엑셀에 `USD`로 기재한 경우에는 공개 `USDT/USD` 시세를 곱해 평가한다.
- 엑셀에 선택 열 `시장`과 텍스트 형식의 `종목코드`를 함께 제공하거나 종목 상세의 원천 식별자에 `stock:KR:국내코드`, `stock:US:미국티커`, `token:XT:토큰티커`를 지정할 수 있다. 엑셀 종목명 오탈자로 시세가 연결되지 않은 행은 종목 상세의 원천 식별자 항목에 유사 상장명 후보 코드를 안내한다. 토큰화 주식은 Kraken USD 거래쌍의 참고 가격을 별도 표시하며 기초주식 연결은 연구 근거로만 쓴다.
- 일봉 수집기는 공개 목록을 순환해 한국·미국 현지 거래일의 시가·고가·저가·종가를 저장한다. 국내 Naver 일봉의 당일 값은 같은 종목의 시장 마감 시세와 대조한 뒤 반영한다. Yahoo 일봉은 정규장 마감 시각을 확인하며, Kraken은 UTC 기준 미완성 마지막 봉을 제외한다. 최초 장중 조회값을 시가로 사용하지 않는다. 별도로 수신한 시장 마감 시세는 일봉의 시가 확보 전에도 조회할 수 있다.
- 일봉은 원천·거래일로 중복을 제거하고 정정 횟수와 확인시각을 보관한다. 주봉과 월봉은 첫 관측 거래일 시가와 마지막 관측 거래일 종가를 집계한다. 가격 등락은 배당과 비용을 제외한 원천 종가 기준이다. 120일선은 120거래일 단순평균이다. 비교 시장의 거래가 확인된 중간 날짜가 빠지면 해당 평균을 보류한다. 1년 등락은 전년 동월일 또는 그 이전 최근 거래일을 기준으로 계산한다. 원천이 서로 다른 시계열을 이어 붙이지 않는다.
- 개인 계좌 DB에는 KST 날짜별 실제로 관측된 마지막 수량·평가액·손익·비중·시세/환율 시각을 기록한다. 원장을 가져오기 전 보유 내역과 실현손익은 역산하지 않는다. 기존 입출금 조정 성과는 포트폴리오의 성과 메뉴에서 조회한다.
- 브라우저 창을 닫아도 실행 중인 로컬 서비스는 수집을 계속한다. Mac이 꺼져 있으면 다음 실행 때 공개 시세 이력을 재수집한다. 공개 이력은 `python3 -m private_accounts price-history`로도 점검할 수 있고, 기존 `daily-review --refresh`에도 포함된다. 전체 상장목록의 첫 수집에는 시간이 걸린다. 수집 실패와 마지막 저장값은 화면에서 확인한다.

자동 일봉 조회 실패에 한해 `research-import stock-bars --checked-at <확인시각>`는 독립 확인한 고정 공개 원천의 JSON 배열을 받는다. 각 원소의 필드는 `venue,symbol,currency,url,rows`이고, 각 행은 `[YYYY-MM-DD,시가,고가,저가,종가]` 문자열 배열이다. 지원 대상은 기존 공개 시장 표본의 Stock Analysis 종목별 과거가격 페이지와 Pubmarks가 공개한 미국 주식 일봉 원장이다. 국내 정규장의 시가만 확인했을 때는 같은 고정 원천의 종목·통화·원문·거래일·시가·원문 게시시각을 stock-opens로 별도 저장한다. 당일 완료 일봉에는 원문의 마감 게시 시각을 published_close_at에 함께 기록하고 시장 마감 시세와 대조한다. 개인 입력·수량을 포함하는 파일은 이 명령의 입력으로 사용하지 않는다.

### 퀀트 연구

투자 매니저에서 **퀀트 연구**를 선택하거나 보유 종목 행의 같은 이름 링크를 연다. 색상이 있는 116개 셀은 각각 5~120일선의 공통 학습 기간 비용 후 수익률이다. 셀을 누르면 해당 선의 체결, 단순 보유 대비 누적성과와 낙폭을 볼 수 있다. 이 조작은 사전에 선택한 후보를 바꾸지 않는다. 최종 구간을 열람한 뒤 다른 셀을 고르는 비교는 탐색용이다.

동일 시장·종목·통화 안에서 검증 가능한 길이와 연속 학습 기간 순으로 단일 원천을 선택한다. 학습 구간의 종가 결측이나 가격 단절 뒤에는 워밍업을 다시 시작한다. 최종 구간의 가격이나 성과는 원천 선택에 쓰지 않는다. 최종 구간에 결함이 있으면 과거 후보를 보존하고 최종 판정을 보류한다. 최소 394봉은 워밍업 121봉, 최초 학습 최소 126봉, 순차 평가 42봉씩 최소 두 번, 최종 평가 63봉으로 나뉜다. 워크포워드에서는 이전 학습 구간을 확장하며 왕복 체결 2회 이상 후보의 비용 후 수익률을 비교한다. 마지막 후보는 최종 63봉 직전에 고정한다. 순차 평가의 초과수익 중앙값, 최종 구간의 왕복 횟수·초과수익, 인접 ±2일선의 초과수익을 함께 점검한다. 선정은 해당 원천·비용 시나리오에서 관측한 상대 성과에 대한 판정이다.

데이터가 추가되거나 정정되면 새 입력으로 다시 계산한다. 기존 실행의 시가·종가, 관측된 시장 거래일, 비용 가정, 전략 버전, 기간별 성과와 판정은 내용 해시별로 Mac의 개인 폴더에 보관한다. 보유 원장 금액이나 수량은 백테스트 자본으로 사용하지 않는다.

**운영 자료 재대조.** 16:01:13과 16:01:47 KST에 실제 매니저의 자동 갱신 HTML 생성 경로를 운영 자료로 두 번 실행했다. 두 시점 모두 각 행의 평가 단가·평가액·손익·수익률·비중이 로컬 계산 결과와 일치했고, 그 사이 공개 수집 성공 기록과 평가 결과가 달라졌다. 종가 적용분과 원장 대체분이 함께 있었다. 실행 중인 서비스에 대한 루프백 접속은 작업 환경의 접근 제한으로 실패했으므로, 기존 브라우저가 이 버전을 수신했다는 확인은 보류한다.

### 바이낸스 토큰화 주식과 공개 시장 이력

`python3 -m private_accounts.binance_daily`는 공개 상장 목록의 bStocks 25종 및 BTC·ETH의 USDT 현물 일봉을 갱신한다. 토큰 일봉은 공개 시세 DB의 `price_bar`, 체결수·거래량·거래대금과 테이커 매수량은 `binance_spot_activity`, BTC·ETH 가격은 `data/project.db`의 `binance_spot_daily`에 저장한다. 일봉 경계는 UTC 00시이며 진행 중인 봉과 체결이 없는 봉은 제외한다. API가 반환하는 최근 최대 1,000봉을 조회하며 기존 DB의 과거 행을 보존한다. 공개 종목 목록은 상장 공지에 맞춰 관리한다. 계좌별 매칭은 로컬에서 거래소와 토큰 심볼로 수행한다. bStocks의 비용 민감도 기준은 편도 수수료 10bp, 반스프레드 10bp, 슬리피지 5bp, 모의 매도세 0bp이다. 실측 호가와 계좌별 세율은 미반영이다.

보관 원문은 로컬 `.local/public_market_sources/`에서 확인할 수 있다. 바이낸스 원문은 `--snapshot 파일`로 재실행한다. 업비트·비트겟·바이비트·환율 응답은 `python3 -m private_accounts.spot_history_import 파일 --cutoff YYYY-MM-DD`로 반영한다. cutoff는 미완료 첫 UTC 날짜이며 원달러 환율은 공표일만 저장한다. 기존 시장 DB가 빈 경우 저장소의 `data/project.db.tar.gz` 안 SQLite의 무결성을 확인해 복원한 후 실행한다.

같은 명령으로 바이낸스 BTC·ETH 선물 원문도 재생한다. 일별 평균 펀딩비, 선물 고저가 변동폭(고가와 저가 차이 ÷ 종가), 글로벌 계정·상위 트레이더 포지션 롱숏 비율과 테이커 거래량을 기록한다. 미결제약정은 기초자산 수량과 USDT 명목액을 `binance_open_interest_daily`의 별도 열에 보존한다. 기존 `sum_open_interest` 열은 수집기별 단위가 다르다. 현물 주봉은 월요일부터 일요일까지 7개 일봉이 모두 있을 때 생성한다.
