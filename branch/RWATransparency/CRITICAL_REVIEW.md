## 🚨 핵심 문제: 순환 논리 (Circular Logic) / 자기 실현적 예언

### 발견된 치명적 결함

현재 분석의 **가장 심각한 문제**는 **데이터 생성 과정에 이미 가설이 내재되어 있다**는 것입니다.

#### 문제 코드 1: `build_panel_data.py` (Line 62-63)
```python
# 가격 시뮬레이션 (TDT 높을수록 변동성 낮음)
base_vol = 0.03 * (1 - tdt / 200)  # TDT 높을수록 변동성 감소
daily_return = np.random.normal(0.0005, base_vol)
```
**문제**: 변동성이 TDT의 함수로 **직접 정의**됨. 
→ H2("TDT ↑ → Volatility ↓")는 **검증이 아니라 데이터 생성 규칙의 재현**일 뿐.

#### 문제 코드 2: `build_panel_data.py` (Line 65-67)
```python
# 거래량 시뮬레이션 (TDT 높을수록 유동성 좋음)
base_volume = mcap * 0.01 * (1 + tdt / 100)
```
**문제**: 거래량이 TDT의 함수로 **직접 정의**됨.
→ H1("TDT ↑ → Illiquidity ↓")도 **자동으로 성립**하게 설계됨.

#### 문제 코드 3: `build_panel_data.py` (Line 75-79)
```python
if shock:
    shock_sensitivity = (100 - tdt) / 100
    shock_impact = 0.04 * shock_sensitivity
    daily_return -= shock_impact
```
**문제**: 충격 민감도가 TDT의 함수로 **직접 정의**됨.
→ H3("TDT ↑ → 충격 완화")도 **자동으로 성립**.

## 📋 상세 비평 (심사위원 관점)

### 1. 방법론적 결함 (Critical)

| 문제 | 설명 | 심각도 |
|------|------|--------|
| **순환 논리** | 가설이 데이터 생성 규칙에 내재 → 검증이 무의미 | 🔴 치명적 |
| **시뮬레이션 데이터** | 실제 RWA 시장 데이터가 아닌 합성 데이터 사용 | 🔴 치명적 |
| **TDT 점수도 랜덤** | `calculate_tdt.py` Line 148-151: 오프체인 데이터 없으면 랜덤 생성 | 🔴 치명적 |
| **시간 불변 TDT** | 각 자산의 TDT가 180일 동안 **동일한 값** 유지 | 🟠 심각 |

### 2. 내생성 문제 (Endogeneity)

- **역인과**(Reverse Causality): "TDT가 좋아서 가격이 안정"인지 "가격이 안정된 자산이 정보 공개를 잘 하는지" 구분 불가
- **누락변수**(Omitted Variable): 발행사의 규모, 규제 준수 수준, 시장 성숙도 등 통제 안 됨
- **동시성**(Simultaneity): TDT와 시장 변수가 동시에 결정될 가능성

### 3. 표본 문제

- 19개 자산 중 상당수가 **스테이블코인**(USDT, USDC, DAI 등)
- 스테이블코인과 RWA 토큰(ONDO, BUIDL)의 특성이 본질적으로 다름
- **표본 이질성**(Heterogeneity)으로 인한 편향 가능성

### 4. 측정 문제

- **TDT 지표의 타당성**: latency/completeness/consistency가 "투명성"을 정말 측정하는가?
- **가중치 임의성**: 동일 가중치(1/3:1/3:1/3)의 이론적 근거 부재
- **필수 필드 선정**: 8개 필드가 왜 "필수"인지 근거 없음

## 📝 논문에 명시해야 할 한계점 (Limitations)

1. 본 연구는 **프레임워크 제안 및 파일럿 검증** 성격이며, 실제 시장 데이터 기반 full-scale 실증은 후속 연구로 남김
